# Planned infrastructure

A concept for the IT infrastructure is required as the basis for this project. In order to be able to evaluate the numerous available solutions and concepts, we have defined nine evaluation criteria:

- Updates: How can the solution be kept up to date?
- Backups: How does the creation and import of backups work, especially with regard to large amounts of data?
- Simple deployment: Is the solution easy to set up or is there a high initial hurdle that makes it difficult for cities or new developers to get started, for example?
- Variables: Can variables be used to e.g. create a user with credentials xy when creating?
- Windows support: To avoid having to maintain two different setups (server/training computer), the solution should also work under Windows
- Scalable hardware: Is it possible to react to future requests by extending the hardware
- Scalable instances: Is it possible to copy an instance (Dashboard, FIWARE, etc.) for another customer
- One network per bundle: If several instances of the same application (bundle) are running on the infrastructure for e.g. city A and city B, they should ideally not be able to access each other.
- Monitoring: Is it possible to monitor the availability and hardware usage with on-board resources?

## Decision

After comparing the options and carrying out a detailed analysis and weighting of the requirements, we came to the conclusion that Docker Compose currently represents the best possible solution. The key points for this solution are:

- New employees can be trained quickly
- very few dependencies that need to be updated regularly
- The same setup can run on the training computer and the server, Windows is also supported
- ComposeFiles can also be used for Kubernetes if scaling is necessary in the future [kompose](https://kompose.io/)
