# Traefik Configuration Documentation

## Overview

This configuration sets up Traefik as a reverse proxy, with automatic SSL certificate generation via Let's Encrypt, HTTP
to HTTPS redirection, and a secure API dashboard. It also includes basic authentication for the dashboard and utilizes
Docker as a provider to dynamically manage services.

## Traefik Settings

### API and Dashboard

- **Dashboard:** The dashboard is enabled, allowing you to monitor the status of Traefik and its services.
- **Insecure Mode:** The dashboard is currently set to be accessible without HTTPS (`insecure: true`). This is
  recommended only for local development. In production, set this to `false` and secure it with TLS.
- **Basic Authentication:** The dashboard is protected by basic authentication using a username and a hashed password.

### Entry Points

- **web:** This entry point listens on port `80` and is used for HTTP traffic. It is configured to automatically
  redirect all traffic to HTTPS (entry point `websecure`).
- **websecure:** This entry point listens on port `443` and handles HTTPS traffic. It uses Let's Encrypt to
  automatically manage SSL certificates.

### Certificates Resolver (Let's Encrypt)

- **Let's Encrypt:** Traefik is configured to use Let's Encrypt's ACME protocol to automatically request and renew SSL
  certificates. The certificates are stored in `/traefik/acme.json`, and the file needs to have proper read/write
  permissions for Traefik.
- **Email:** The email is used for Let's Encrypt registration.

### Providers

- **Docker:** Traefik is connected to Docker and watches for changes in container status. It only exposes services
  explicitly labeled for exposure (`exposedByDefault: false`).
- **File:** Additional static configuration for Traefik is loaded from the file `/traefik/traefik_api.yml`.

### Middleware

- **Basic Authentication:** The middleware `simpleAuth` is used to secure the dashboard.
  The users are read from the environment variable `TRAEFIK_BASIC_AUTH` in `.env` (htpasswd format, e.g. created with `htpasswd -nb admin <password>`).
  The domain of all routes is read from `DOMAIN`.

## Security Recommendations

- Set `insecure: false` in production to ensure the dashboard is only accessible via HTTPS.
- Regularly rotate the admin password and ensure the password is securely hashed before adding it to the configuration.

## Traefik with mkcert Certificates for Localhost

When using Traefik locally, generating SSL certificates for custom domains such as `localhost` can cause errors like the following:

```
ERR Unable to obtain ACME certificate for domains error="unable to generate a certificate for the domains
[portainer.localhost]: acme: error: 400 :: POST :: https://acme-v02.api.letsencrypt.org/acme/new-order ::
urn:ietf:params:acme:error:rejectedIdentifier :: Invalid identifiers requested :: Cannot issue for \"portainer.localhost\":
Domain name does not end with a valid public suffix (TLD)" ACME CA=https://acme-v02.api.letsencrypt.org/directory
acmeCA=https://acme-v02.api.letsencrypt.org/directory domains=["portainer.localhost"] providerName=le.acme
routerName=portainer@docker rule=Host("portainer.localhost")
```

### Why This Happens

ACME certificate providers like Let's Encrypt require domain names to end with a valid public suffix (Top-Level Domain, or TLD). Domains such as `localhost` or custom development domains like `portainer.localhost` do not qualify, as they lack a recognized public suffix like `.com` or `.org`. As a result, these domains are rejected during the certificate issuance process.

### Solution: Use MKCert to Create Local Certificates

[MKCert](https://github.com/FiloSottile/mkcert) is a simple tool designed for creating locally-trusted certificates. It sets up a local Certificate Authority (CA) on your machine and generates valid certificates for development environments, including `localhost` and custom domains.

### Step 1: Run MKCert to create root and domain certificates

We added an docker image with mkcert to the development setup to create certificates for each domain in `/traeffik/certs/`.

Besides the domain certificates the docker container creates a root certificate in `/traeffik/root-cert/` that needs to be added to the trusted root certificates of the used os.

### Step 2: Configure Traefik to use the custom certificates

Update your Traefik configuration to use the certificates generated by `mkcert`. Below is an example configuration:

```yaml
# traefik_api.yml

tls:
  certificates:
    - certFile: "/traefik/certs/portainer.localhost.pem"
      keyFile: "/traefik/certs/portainer.localhost-key.pem"
    - certFile: "/traefik/certs/grafana.localhost.pem"
      keyFile: "/traefik/certs/grafana.localhost-key.pem"
    - certFile: "/traefik/certs/traefik.localhost.pem"
      keyFile: "/traefik/certs/traefik.localhost-key.pem"
  stores:
    default:
      defaultCertificate:
        certFile: "/traefik/certs/localhost.pem"
        keyFile: "/traefik/certs/localhost-key.pem"
```

Place the certificates in the `/traefik/certs/` directory (or any directory of your choice), and ensure that the paths in the configuration match the actual file locations.

# Routing with Traefik

To route your services using Traefik, you need to add specific labels to your service configuration. You don't have to expose any ports manually; instead, specify the port your service uses for communication via labels.

For example, if your service communicates on port `1880`, set the following label:

```yml
"traefik.http.services.nodered.loadbalancer.server.port=1880"
```

Below are examples of how to configure these labels for both development and production environments.

## Development Example

```yml
labels:
  - "traefik.enable=true"
  - "traefik.http.routers.nodered.rule=Host(`nodered.localhost`)"
  - "traefik.http.routers.nodered.tls=true"
  - "traefik.http.services.nodered.loadbalancer.server.port=1880"
```

### Explanation

- **traefik.enable**: Enables Traefik for this service.
- **traefik.http.routers.nodered.rule**: Defines the routing rule. Requests to `nodered.localhost` will be routed to this service.
- **traefik.http.routers.nodered.tls**: Enables TLS for the router.
- **traefik.http.services.nodered.loadbalancer.server.port**: Specifies the port on which the service is listening.

## Production Example

```yml
labels:
  - "traefik.enable=true"
  - "traefik.http.routers.nodered.rule=Host(`nodered.example.com`)"
  - "traefik.http.routers.nodered.tls=true"
  - "traefik.http.routers.nodered.tls.certresolver=le"
  - "traefik.http.services.nodered.loadbalancer.server.port=1880"
```

### Explanation

- **traefik.enable**: Enables Traefik for this service.
- **traefik.http.routers.nodered.rule**: Defines the routing rule. Requests to `nodered.example.com` will be routed to this service.
- **traefik.http.routers.nodered.tls**: Enables TLS for the router.
- **traefik.http.routers.nodered.tls.certresolver**: Specifies the certificate resolver (e.g., `le` for Let's Encrypt) for automatic SSL certificates.
- **traefik.http.services.nodered.loadbalancer.server.port**: Specifies the port on which the service is listening.

### Notes

- Ensure that your domain's DNS records point to your server's IP address.
- The certificate resolver (`le` in this case) must be configured in your Traefik setup to handle SSL certificates from Let's Encrypt.

## Additional Tips

- **No Port Exposure Needed**: Since Traefik acts as a reverse proxy, you don't need to expose your service's ports externally.
- **Dynamic Configuration**: Traefik automatically detects services with these labels and updates its configuration without requiring a restart.
